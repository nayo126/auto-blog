Copilotを使い始めたものの、「思ったような答えが返ってこない」「ChatGPTより精度が落ちる気がする」と感じていませんか。実は、Copilotは指示の出し方ひとつで出力が劇的に変わるツールです。

特にGitHub Copilot Chatや Microsoft 365 Copilotは、ChatGPTやClaudeと違って「業務文脈の中で動く」前提で設計されています。だからこそ、汎用的なプロンプトをそのまま流用しても本領を発揮しません。

この記事では、Copilotで成果を最大化するプロンプトの作り方を、7つのステップとコピペで使えるテンプレートに分けて解説します。

## 結論：Copilotプロンプトは「役割×文脈×制約」の3層構造で書く

結論から言うと、Copilotで安定して高品質な出力を得るプロンプトは、**①役割定義 ②文脈情報 ③制約条件**の3層で構成されています。

理由はシンプルで、Copilotは「ユーザーが今やっている作業の延長線上で答える」よう最適化されているからです。GitHub Copilotならコードのコンテキスト、Microsoft 365 CopilotならOutlookやTeamsの会話履歴を自動で参照します。つまり、人間側が**追加で何を伝えるか**で出力が決まります。

具体的には、こんな構造です。

```
あなたは[役割]です。
[現在の状況・前提]の中で、
[目的]を達成するために、
[制約条件・出力形式]に従って回答してください。
```

たとえば、海外の開発者コミュニティで共有されているプロンプト分析でも、3層構造を意識したものは1層構造（指示だけ）と比べて、生成結果の修正回数が大幅に減るとの報告が多く見られます。曖昧な「○○について教えて」では、Copilotの強みは引き出せません。

## ステップ1〜3：プロンプトの土台を作る

まずはプロンプトの骨格を作る3ステップを押さえましょう。ここを飛ばすと、どんなに後半を工夫しても結果が安定しません。

### ステップ1：役割を1行で定義する

最初の1行で「あなたは○○です」と役割を与えるだけで、回答の専門性が変わります。

- ❌「コードレビューして」
- ⭕「あなたはTypeScriptとReactに精通した10年経験のシニアエンジニアです。以下のコードをレビューしてください」

GitHub Copilot Chatでは、役割定義によって使用される語彙やレビュー観点が明確に変わります。

### ステップ2：文脈を「箇条書き」で渡す

Copilotは長い文章よりも箇条書きで整理された情報を処理しやすい傾向があります。

```
前提：
- プロジェクト：ECサイトの管理画面
- 言語：TypeScript / Next.js 15
- 課題：注文一覧ページのレンダリングが3秒以上かかる
- 制約：既存DBスキーマは変更不可
```

### ステップ3：目的とゴールを明確化する

「何を達成したいか」を数値や状態で示します。「速くしたい」ではなく「初回描画を1秒以内にしたい」と書く。これだけで、提案される解決策の質が変わります。

## ステップ4〜5：精度を引き上げる「制約」の入れ方

土台ができたら、次は出力の精度を引き上げる工夫です。

### ステップ4：出力フォーマットを指定する

Copilotに「Markdown形式で」「表形式で」「コードブロックは言語タグ付きで」と明示します。フォーマット指定がないと、毎回バラバラの形で返ってくるため、レビューや再利用がしづらくなります。

おすすめの指定例：

- **コード提案時**：「変更箇所のみdiff形式で。変更理由を1行コメントで添える」
- **設計相談時**：「メリット・デメリット・推奨理由の3項目を箇条書き」
- **メール下書き時**：「件名・本文・要約の順で出力」

### ステップ5：禁止事項を明示する

意外と効くのが「やってほしくないこと」を書くことです。

```
制約：
- 既存ライブラリの大幅追加はしない
- コメントは英語ではなく日本語で
- 推測で実装せず、不明点は質問してください
```

特に最後の「不明点は質問して」は重要です。Copilotは指示がないと、足りない情報を勝手に補完して進めようとします。これを抑えることで、的外れな提案が大幅に減ります。

## ステップ6〜7：実務で差がつく応用テクニック

ここからは、副業や本業の生産性に直結する応用編です。

### ステップ6：「Few-shotプロンプト」で出力スタイルを統一する

Few-shotとは、お手本を1〜3個見せてから本題を依頼する手法です。Microsoft 365 Copilotでメール下書きをするとき、過去の自分のメールスタイルを2通貼ってから「同じトーンで書いて」と頼むだけで、別人のような出力が自分の文体に近づきます。

```
以下は私が普段書くメールの例です：
【例1】〜〜〜
【例2】〜〜〜
上記のトーンで、来週の打ち合わせ日程調整メールを作成してください。
```

### ステップ7：プロンプトを「資産化」する

毎回ゼロから書くのは非効率です。よく使うプロンプトはテンプレ化して保存しましょう。

おすすめの管理方法：

1. **GitHub Copilot**：`.github/copilot-instructions.md` にプロジェクト共通ルールを記載
2. **Microsoft 365 Copilot**：Copilot Labのプロンプト保存機能を活用
3. **個人ストック**：Notionやテキストファイルで「コードレビュー用」「議事録要約用」など用途別に整理

副業でAIライティングや開発受託をしている人ほど、このテンプレ資産がそのまま納品速度に直結します。テンプレ20個を持っているだけで、1案件あたりの作業時間が半分以下になるケースも珍しくありません。

## まとめ：明日から使えるCopilotプロンプトの最短ルート

Copilotで成果を出すプロンプトは「役割×文脈×制約」の3層構造が基本。そこに目的の明確化、フォーマット指定、禁止事項、Few-shot、テンプレ化を加えれば、出力の質は段違いになります。

まずは今使っているCopilotで、今日扱う作業ひとつだけでもこのフレームに当てはめてみてください。1週間続ければ、AIに振り回される側から、AIを使いこなす側に立ち位置が変わります。プロンプトは才能ではなく型。型を覚えた人が、確実に先に進めます。
